# PR #35 — ninth review and tenth-document follow-up

**Updated in the same [PR #35](https://github.com/MonkeyDo-Site/MonkeyDoWebsiteNewCode/pull/35).** This gallery includes the owner's tenth-document corrections to the ninth screenshots and the deployed site. Please refer to a gallery number when commenting; we will update this same PR and gallery. The owner now authorizes merge and deployment while deferring actual Banquest field verification. Further comments can follow the deployment. See the [as-built test guide](../../NINTH_TENTH_TEST_GUIDE.md).

There are **35 numbered screens**, each with **desktop (1440px)** and **phone (390px)** images. All filenames use **v2** to avoid old cached images. **22–35** show the added public/recovery/fee screens; **01–21** are refreshed staff/pricing/waiver views. In **15–16**, Comments now sits between price and Messages; **19** shows the baby-only price matching the child price. **28** is the approved clearer two-profile wording.

**Banquest field rendering remains unverified.** The workspace's network policy still blocks `tokenization.sandbox.banquestgateway.com`. The suspected PR #34 container-layout regression has been addressed by restoring the provider layout, but the card fields in **04, 22 and 34 are simulated** and do not prove the real provider layout is fixed. Actual hosted-frame verification follows the domain grant. No real payment, email or storage provider was contacted for these images; provider outcomes were injected into the local ledger. Records, signatures and comments are fictional.

Arrival live pricing updates before the waiver answer. Only final confirmation records arrival/payment. Use remaining balance fills the unallocated non-card amount; cash change remains deferred. A declined booking offers explicit Retry card and Review remaining payment; pending/uncertain operations never automatically retry. Gift cards remain available at ordinary arrival but never for cancellation/no-show fees. Zelle prepayments still reconcile against the fee.

New waivers always require minor names. Staff may explicitly attest coverage and acknowledge a name-count discrepancy; the actor/time/counts remain audited. New pricing versions link baby-only/adult-only admission to the child price. Existing accepted quotes and signed records remain intact. Profile recovery verifies names before exposing stored phones and requires an explicit profile choice/confirmation; it does not merge or edit customer records.
