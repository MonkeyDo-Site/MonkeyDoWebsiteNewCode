# Ninth batch — screenshot gallery

**Draft PR [#35](https://github.com/MonkeyDo-Site/MonkeyDoWebsiteNewCode/pull/35) is ready for owner screenshot review.** Please refer to the gallery number when giving a comment. We will update this same PR and gallery as you review. Merge, the ZIP and the single deployment command follow your final approval.

There are **21 labelled screens**, each with a **desktop (1440px)** and **phone (390px)** image. The links open the original full-page screenshots; the expandable previews use the same files. The last column maps to comments in Ninth Batch of Comments.docx. The source screenshots predated PR #34; these screens include the merged eighth-batch corrections.

Start with **01–07** for arrival, the waiver-count warning and preserved card/signing returns; **08–11** for split payments; **12–14** for actual outcome presentation; **15–17** for the compact backend and booking comments. **18–21** cover pricing and mandatory waiver names.

All records, signatures, receipts, comments and provider results are fictional local review fixtures. The card frame is simulated and provider outcomes are injected into the local ledger; no real payment, email or storage provider was contacted. Actual Banquest iframe rendering still needs a hosted check. These images do not establish issuer approval or real delivery. Historical signed evidence is not rewritten.

Every new electronic/paper waiver now requires minor names, as explicitly reconfirmed by the owner. No blank-name adult-only exception is retained. Staff coverage attestation is separate: when the recorded names are fewer than visiting minors, the warning requires an explicit Yes before final arrival. That decision and staff actor/time are retained in checkout/audit records.

**Cash change is deferred.** The amount rows record funds applied to the booking. Use remaining balance accounts for recorded Zelle and removes the card processing fee when no card portion remains. Clearing an abandoned split draft does not delete recorded receipts.

The arrival error investigation reproduced an unbound-form error-handler path: a rejected initial capacity preview could become HTTP 500. It now renders validation normally. This does not claim access to the original hosted traceback.

Booking comments add one nullable booking association to the existing comment record (migration 0052); existing comments remain intact. The reviewed deployment allowlist is extended for that additive migration, with existing restricted permissions and pending-migration guards. No hosted migration, merge, deployment, integration activation or credential change has been performed for this draft PR.
