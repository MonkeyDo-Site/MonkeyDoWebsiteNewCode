# Eighth batch — screenshot gallery

**The owner approved PR [#34](https://github.com/MonkeyDo-Site/MonkeyDoWebsiteNewCode/pull/34) for merge and deployment preparation.** This gallery retains the approved review screens and stable numbering. [Post-deployment testing guide](../../EIGHTH_BATCH_TEST_GUIDE.md).

Each numbered screen has a **desktop (1440px)** and **phone (390px)** image. Click Desktop or Phone to open the full image; the expandable previews below are the same uncropped screenshots. The final column maps back to the comments in your Word document.

Start with **07–08** for the requested 732-555-0147 examples and **10–13** for the one-button confirmation flow. **21** shows the updated email subject/body. **19–20** are recovery examples for a deliberately interrupted response, not the normal booking steps.

All records and card fields here are fictional. The provider card frame is simulated; these images do not establish real Banquest iframe rendering or issuer approval. No external payment, email or storage request was sent. Clubs are hidden, and public membership purchase remains disabled. The email preview includes a mail-client-style To/Subject header for review; that header is not added to the email body. Its subject has no year/reference, and there is no repeating date/time preheader.

## Updated after your screenshot comments

**Version 4 replaces all version 3 images; screens 19–20 use version 5 for the final approved retry wording.** Full-strength page content, two-by-two phone photos, lowered contact address, rose session heading, revised session-card spacing, phone progress in two columns (1–3 / 4–5), markers after colons, error focus without a visible box, narrower card-number field and single-line security-code label, cream Zelle instructions and compact time ranges are included.

**09 and 18:** the previous box was a browser focus outline, not a screenshot annotation. The error still receives focus and scrolls into view; the outline on the error container is removed. Input and button keyboard outlines remain.

**19–20:** this deliberately interrupted connection example is exceptional. The final approved message is **Your booking is not confirmed. We couldn't confirm your card selection for this booking, please try again**; the last phrase is a hyperlink. The inline **please try again** link checks the already-started attempt, or reloads an already-saved card selection, without another card submission or payment. A recovered card still requires an explicit Confirm booking. If the result remains uncertain, the booking stays unconfirmed.

**Card fields:** the preview frame shows the requested proportions and the application now passes those widths through Banquest’s documented styling controls. The gallery uses a simulated provider frame; actual provider rendering must be checked after deployment.

## Review and deployment

The ordinary booking still collects admission only after staff arrival review. Processing is visibly unconfirmed; invalid/uncertain setup cannot silently create a booking. Historical records and signed evidence are preserved. The original unexpected legacy-flow code paths are blocked for new completed-workflow bookings; the historical legacy records remain read-only history.

The owner approved merging the PR and preparation of the pinned browser ZIP and single PowerShell deployment command. Hosted deployment is performed by the owner with that command; no new integration activation is part of this release.
